# MASVS mapping for register line R-02, draft evidence for the recorded owner
# Environment: repository main @ 9ae0c8b, re-reviewed 13 November 2026
# Standard note: the register line cites "MASVS L1" from the 2024 structure
# (categories V1 to V12 with verification levels). The cited URL now serves the
# restructured MAS standard: eight categories, 24 controls, levels dropped.
# This map uses the live standard and says so, rather than quoting a retired
# numbering from memory.
# Verdicts: CHECKED (evidence exists in this repo), N/A (mechanism absent by
# construction), DEFERRED (not implemented, named), GAP (known weakness, documented).
# Evidence paths are repo relative. Functional trials alone do not complete the
# map; each row names the actual check.

STORAGE-1  secure storage of sensitive data
  verdict: CHECKED (former AsyncStorage gap closed)
  observation records live in device-private SQLite inside the app sandbox,
  capture photos in app-private files, all server data behind RLS, private
  buckets carry the delete and MIME caps (see storage_bucket_config_note.txt)
  FIXED 4 November after first disclosure: the mobile auth session moved from
  AsyncStorage to expo-secure-store (Android keystore, iOS keychain) through a
  chunked adapter, because the live session measured 2220 bytes over the 2048
  byte Android item limit and the storage key 34 characters over the 31 key
  limit; nine behaviour tests pin both limits and the one-time legacy
  migration, see mobile/src/lib/session-store-core.test.mjs. The original
  exposure: session persisted unencrypted at rest in AsyncStorage
  (mobile/src/lib/supabase.ts:13 as it stood)

STORAGE-2  prevents leakage of sensitive data
  verdict: CHECKED
  committed artefacts scrubbed of session tokens, tester identities and GPS
  coordinates (privacy review, docs test convention), qr_code removed from all
  public payload selects (R-10, see qr_public_exposure_note.txt), the interaction
  log records routes and targets only, no credential fields, bucket MIME allow
  lists block arbitrary stored content (R-07), and the web species-photo upload
  content-sniffs the file header and stores the sniffed type rather than the
  browser-declared one (13 November hardening, web/src/lib/photo-mime.ts)

CRYPTO-1   current strong cryptography
  verdict: CHECKED
  no custom cryptography exists in either app (code review), password hashing
  is bcrypt server side through Supabase Auth, transport is TLS

CRYPTO-2   key management per best practice
  verdict: CHECKED
  no key material ships in app code beyond the public anon key by design,
  the service role key is server only, its rotation is the open item #41

AUTH-1     secure authentication and authorisation protocols
  verdict: CHECKED
  email and password through Supabase Auth with JWT sessions, authorisation
  proven by the 41 assertion RLS matrix (pgtap_battery.txt) and the browser
  role-gate flows, not assumed

AUTH-2     secure local authentication
  verdict: N/A
  no local or biometric unlock exists, sign-in is always network based

AUTH-3     sensitive operations require additional authentication
  verdict: CHECKED
  approve, reject and species mutation are gated server side by role via
  current_role() checks, proven by the battery negatives and by the officer
  403 on the telemetry route (web API tests), UI hiding is not the control

NETWORK-1  secures all network traffic
  verdict: CHECKED
  zero cleartext http endpoints in app code (grep of mobile/src and web/src),
  the only 127.0.0.1 references are test and local-clone paths gated in CSP

NETWORK-2  identity pinning for remote endpoints
  verdict: DEFERRED
  no certificate pinning, standard omission at prototype scale, named here
  rather than left silent

PLATFORM-1 secure IPC

PLATFORM-2 secure WebViews
