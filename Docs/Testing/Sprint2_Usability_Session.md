# Sprint 2 short usability session

## Purpose

Observe whether someone can complete the main tasks without being shown where to tap. This is a small formative study, not a representative population study. Use any participant count required by the agreed acceptance plan. Three to five available participants can provide useful initial feedback, but do not replace an existing sample-size commitment.

## Preparation

Allow about 15 to 20 minutes per participant. Ask classmates or other volunteers who did not build the screens. Record their relevant experience and use anonymous IDs such as P01. Explain that you are testing the app, not them. Ask permission before recording their screen or comments. Use test accounts and test records.

Record the app revision, device, operating system, connection state and date. Prepare one known QR code and one unknown code. Give officers a pending test record with photos. Mark role-specific tasks not attempted when the participant has no suitable account.

## Task script

Read each task without naming the button to press. Start timing after reading it. Stop when the stated outcome is reached or the participant stops. Record any help you give.

| Task | Prompt | Completion outcome |
|---|---|---|
| U01 | Find a plant in the species guide and tell me its conservation status | Correct species and status identified |
| U02 | Scan this known tag and find its record | Correct record displayed |
| U03 | Scan this unknown tag and return to scanning | Outcome understood and scanning available again |
| U04 | Move between the scanner and species list, then refresh the list | Intended tabs opened and refresh completed |
| U05 | Review the supplied photograph for this pending observation | Officer opens the larger photo and can inspect another image if available |

## Results sheet

Copy one row per participant and task. Leave unmeasured results blank. Record failures and assistance as well as successes.

| Participant | Task | Success, assisted, failed or not attempted | Seconds | Errors or hesitation | Help given | Ease rating 1 to 5 | Participant comment |
|---|---|---|---|---|---|---|---|
| | | | | | | | |

After each task ask how easy it was, from 1 for very difficult to 5 for very easy. This is a task-ease question, not a SUS score. Finish by asking what was confusing and what they would change first.

## Report summary

Report the participant count and recruitment method. For each task report independent successes out of attempts, assisted completions, failures and the timing summary. Explain which timings are included. Link anonymised screenshots or notes. List the most important observed problems and any changes made after testing. Retest those changes and preserve the earlier results.

## Existing owner feedback

The owner reported that the phone checks work fine after receiving the checklist for QR codes, permissions, navigation, scanner animation and species states. This is informal owner feedback. Device details, individual task outcomes, timings and screenshots were not supplied. Do not count it as a completed participant session or a measured acceptance result.
