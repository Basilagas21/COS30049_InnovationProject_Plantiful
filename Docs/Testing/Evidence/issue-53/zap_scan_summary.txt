# Observed results (3 November 2026)
Anonymous baseline, 8 rules, 0 High: CSP script-src unsafe-inline (Medium x4), CSP
  style-src unsafe-inline (Medium x5), missing COEP/COOP/CORP (Low), info notes. PASS: 63.
Authenticated baseline, 10 rules, 0 High: same CSP Mediums plus Server header version
  leak (Low x5, nginx front artifact, NOT the deployed app) and caching notes. PASS: 63.
Full active scan, authenticated, 225 instances across 5 rules, 0 High, 0 injection
  findings: CSP Mediums (x46 each, the pages scanned), Server version leak (artifact),
  Modern Web Application + User Agent Fuzzer informational. NO SQL injection, NO
  reflected XSS, NO path traversal, NO command injection, NO CRLF, NO broken access
  control alert, NO CSRF-relevant session fixation finding raised.

# Conclusions for the register
- R-01/SEC-03: repeat scan executed against the app code (clone backend), both contexts,
  dated evidence here. Limitation: local clone, not the deployed hosting layer.
- R-09 (nonce CSP): the scanner found zero XSS injection points, and code review found
  zero innerHTML. The unsafe-inline allowance is therefore a defense-in-depth nicety,
  not a live hole; migrating to nonces touches every page response for no demonstrated
  finding. Recommend: retain with this evidence as the justification (register option
  'retain a justified prototype limitation', now genuinely justified), owner decides.
- R-06: permission negatives are automated (pgTAP 41 assertions + 12 browser role-gate
  flows), the scanner confirms no anonymous user reaches officer surfaces.
